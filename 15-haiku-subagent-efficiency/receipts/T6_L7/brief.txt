# RUNLOG Vocabulary, Tone & Empirical Proof Guide

This document captures all required vocabulary replacements, conversational tone filters, and visual proof mandates. All scripts, narration generation, and Hyperframes compositions must adhere strictly to these rules.

---

## 1. Banned Words & Approved Replacements

| Banned Word / Pattern | Why It Is Banned | Approved Replacement | Example |
|---|---|---|---|
| **"real-world" / "real"** (as fluff) | Sounds like marketing hype and AI-generated filler. Real engineers speak plainly about what was tested. | **"practical"**, concrete descriptions, or omit entirely | ❌ *"We ran five real-world commands"*<br/>✅ *"We ran five practical bash commands"* |
| **"for real" / "literally" / "honest" / "honestly" / "truly" / "really"** | Conversational filler that reduces credibility and signals synthetic script generation. | Omit entirely. State the fact directly. | ❌ *"This literally took 7 seconds"*<br/>✅ *"This took 7.67 seconds"* |
| **"apology" / "apology tax" / "apology loop"** | Theatrical, emotional buzzword trope. Not professional architecture language. | **"frontier recovery loop"**, **"context reload"**, **"multi-paragraph response"**, **"execution halt"** | ❌ *"Claude Code burned tokens on the apology tax"*<br/>✅ *"Claude Code burned tokens on a three-paragraph recovery loop"* |
| **"tax"** (metaphorical) | Overused YouTube prompt-hype jargon. | **"overhead"**, **"delay"**, **"latency penalty"**, **"token consumption"** | ❌ *"Network tax"*<br/>✅ *"Network roundtrip penalty"* |
| **"our GPU" / "our local RX 7900 XTX"** | Unnecessary collective possessive; sounds promotional rather than objective. | **"local GPU RX 7900 XTX"**, **"on an RX 7900 XTX"** | ❌ *"tested on our local RX 7900 XTX"*<br/>✅ *"tested on local GPU RX 7900 XTX"* |
| **"Claude 3.7"** | Outdated model (early 2025). As of September 2026, Anthropic's flagship standard is Claude 4 / 4.5. | **Claude Sonnet 4.5** | ❌ *"frontier models like Claude 3.7"*<br/>✅ *"frontier models like Claude Sonnet 4.5"* |
| **"P. O. S. I. X." (spelled out)** | Unnatural TTS spelling. Developers pronounce it as a single word ("pah-zicks" / "paw-six"). | **"POSIX"** (or phonetically written as a single word) | ❌ *"P. O. S. I. X. exit code 2"*<br/>✅ *"POSIX exit code 2"* |
| **"RUNLOG" in TTS** | Kokoro spells an all-caps token letter by letter ("R U N L O G"). | Spoken as **"run log"**. Keep `RUNLOG` in script, captions and on-screen text; `generate_tts.py` respells it at synthesis time only (`PRONUNCIATIONS`). | ❌ *"Subscribe to R U N L O G"*<br/>✅ *"Subscribe to run log"* |
| **"arm" (experiment jargon)** | Viewers do not know "arm" means one condition being compared; it reads as lab-speak. | **"setup"** ("five setups", "the setup where I did nothing"). Applies to narration, on-screen text and upload notes. | ❌ *"Three runs per arm"*<br/>✅ *"Three runs per setup"* |
| **Em dashes (`—`) and En dashes (`–`)** | Punctuation artifact of AI writing models; causes rendering and line-wrap bugs on mobile video canvas. | Commas, colons, or periods | ❌ *"Kev — a fast reflex — catches it"*<br/>✅ *"Kev, a fast reflex, catches it"* |

---

## 2. Natural Human Speech Rules
- **Casual, matter-of-fact delivery:** Speak like an experienced developer talking casually to a peer. No breathless hype, no theatrical framing.
- **Compact & concise:** If a word can be removed without losing technical meaning, remove it.
- **Show, don't just assert:** If a command is practical or destructive, show the command itself (`git push --force origin main` or `rm -rf /`) rather than repeatedly telling the viewer it is "dangerous" or "real".

---

## 3. The Empirical Proof Mandate
Whenever a number or metric is spoken in narration, the video canvas **must display visual proof** at that exact moment:
- **Duration / Latency:**
  - Spoken: *"took 7.67 seconds to resolve"*
  - Canvas must show: Verbatim terminal execution timer footer (`Duration: 7.67s (7,669ms)`), live stopwatch odometer, or benchmark timestamp log.
- **Token Counts:**
  - Spoken: *"burned over two thousand output tokens"*
  - Canvas must show: Verbatim CLI token counter (`Output: 2,140 tokens`).
- **Verbatim Responses:**
  - When referencing an agent's feedback, show the **full unedited response** in the terminal window chrome, rather than a truncated paraphrase.

---

## 4. Visual Layout Standard (Diagrams Over Dashboards)
- **Ban "Dashboard Syndrome":** Never display boxed SaaS cards or Datadog-style monitoring tiles.
- **Use Connected Diagrams & Flowcharts:** Use connected boxes, animated flow lines, and clear sequential stage swaps.
- **Symmetrical 50/50 Margins:** Ensure all central stages and card stacks have equal left and right margins (1600px width centered on 1920px canvas = 160px left, 160px right).
